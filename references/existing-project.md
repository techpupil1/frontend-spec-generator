# 已有项目流程

当工作区里已经存在前端代码时，使用这条路径。

## 目标

基于当前代码库现状输出一份“知道差距在哪里”的前端规范，而不是写一份脱离现实的空泛新项目规范。

## 工作流

1. 扫描代码库，识别框架、语言、构建工具、路由、状态管理、样式方案、组件库、Lint/Format、测试配置和目录结构。
2. 用非技术化语言总结项目现状。
3. 找出当前实现中不一致、缺失、或未来容易放大的问题。
4. 把这些发现映射到最终文档的八大模块里。
5. 逐模块和用户确认，而不是擅自覆盖现有架构。

## 提问方式

- 从观察结果出发提问，例如：“我看到现在是 `React + Vite + Tailwind`，你是想保留这套栈，还是想借这次规范顺便做迁移？”
- 用结果解释取舍，例如：“保留当前栈能降低迁移成本，切换方案可能改善长期维护，但会增加短期交付风险。”
- 只问还没确定的问题。代码里已经能看出来的事实，不要再让用户重复描述。

## 在最终规范前必须先产出

- 一份简明的项目现状总结
- 一份按模块拆分的差距清单
- 一份经用户确认的变更或缺失项决策
