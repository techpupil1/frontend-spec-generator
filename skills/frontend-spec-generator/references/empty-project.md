# 空项目流程

当用户只有一个产品想法、一段简短描述，或者仓库本身还是空的时，使用这条路径。

## 目标

把模糊的产品概念收敛成一份具体的前端规范，同时不要把产品策划工作全部甩给用户自己完成。

## 工作流

1. 先读取用户描述，推断可能的产品能力、用户角色、核心流程和约束条件。
2. 把推断结果整理成结构化摘要，交给用户修正。
3. 只有在不确定性会明显影响前端架构时，才继续做针对性追问。
4. 确定产品形式：网页、小程序、还是 App；如果是 App，进一步确认安卓、iOS、鸿蒙或跨端范围。
5. 讲清不同产品形态在交付和使用效果上的差异，而不是只抛术语。
6. 在可联网时自行完成竞品调研。
7. 用竞品调研结果辅助给出建议，再和用户确认最终方向。
8. 进入八大模块，逐个确认后再定稿。

## 需求理解规则

- 先推断，再提问。例如：如果用户描述的是知识型产品，就优先推断搜索、分类、内容展示、账号体系这些能力。
- 推断结果要按组呈现给用户确认，不要拆成大量零碎问题。
- 优先确认目标用户、使用频率、核心任务、商业或成本约束、内容复杂度、协作需求和设备场景。
- 当前端相关问题已经足够清楚、足以驱动架构决策时，就停止需求发散。

## 竞品调研规则

- 自行搜索直接竞品和相邻竞品。
- 提取视觉风格、信息密度、导航模型、新手引导方式、商业化信号、关键交互模式，以及对前端设计有影响的点。
- 把竞品调研作为决策输入，而不是要求用户照抄竞品。
- 如果当前无法联网，明确标记"竞品调研待外部验证"。
