# 示例：空项目规范输出

## 输入摘要

面向专业人士构建一款支持桌面端和移动端的知识笔记产品，核心目标是高效记录、分类、搜索和回顾内容。用户主要是咨询顾问、研究员、产品经理这类高频知识工作者。

## 示例规范

# NoteFlow 前端规范

## 1. 视觉风格

### 已确认方向

整体风格偏克制、理性、轻专业感，接近 Notion 和 Craft 之间的中间状态。界面要足够干净，方便长时间阅读和编辑，但不能过于极简导致信息层级不清。

### 设计规则

- 主色使用偏冷静的蓝灰体系，强调效率感而不是社交感
- 大面积背景保持低干扰，内容区强调留白
- 字体采用无衬线正文搭配等宽数字，兼顾阅读和信息扫描
- 卡片圆角中等，阴影轻，避免重拟物
- 默认支持暗色模式，用于夜间记录和长时间使用

### 备注

不追求品牌感特别强的视觉表达，优先保证内容工具的稳定和耐看。

## 2. 技术方案

### 已确认方向

采用 `React + TypeScript + Vite` 作为主栈，优先交付网页版本，后续再评估是否扩展桌面壳或移动端容器。

### 决策理由

- React 生态完整，后续接入编辑器、搜索、状态管理和协作能力更稳
- TypeScript 有助于减少编辑器、筛选器、数据同步等复杂交互下的运行时错误
- Vite 启动快、反馈快，更适合小团队快速迭代
- 首发网页版可以最低成本验证产品方向，避免过早进入原生 App 成本

### 约束条件

- 第一阶段不做离线优先
- 第一阶段不做复杂实时协作
- API 交互以标准 REST 为主，后续再评估增量同步能力

## 3. UI 组件库

### 已确认方向

采用"半成品组件 + 自定义风格"的策略，不直接使用重样式的整套后台组件库。

### 组件范围

- 按钮、输入框、下拉、弹窗、抽屉、Tabs、Tooltip、Toast
- 笔记列表、标签选择器、筛选条、侧边导航、搜索框
- 空状态、加载状态、错误状态组件

### 特殊组件

- 富文本或 Markdown 编辑器
- 命令面板式全局搜索入口
- 标签与知识分类管理面板

## 4. 目录结构

### 已确认方向

按功能模块组织，优先保证"修改一个功能时尽量少跨目录跳转"。

### 建议目录树

```text
src/
  app/
  shared/
  features/
    notes/
    search/
    tags/
    settings/
  pages/
  widgets/
```

### 命名与导入规则

- 页面级入口放在 `pages/`
- 功能逻辑优先归属对应 `features/`
- 跨功能复用逻辑才允许进入 `shared/`
- 禁止 `features/notes` 直接依赖 `features/search` 内部实现

## 5. 模块边界

### 已确认方向

页面不直接散落调用 API，统一经过各自功能模块的数据访问层。

### 状态与通信规则

- 页面负责组合，不负责承载业务规则
- 功能模块内部自行管理局部状态
- 全局仅保留主题、登录态、全局搜索开关等少数共享状态

### 依赖规则

- `pages -> widgets -> features -> shared`
- 下层不能反向依赖上层
- 公共逻辑抽到 `shared` 前必须确认跨两个以上功能复用

## 6. 复用规则

### 已确认方向

默认出现 3 次再提取，避免在产品早期过度抽象。

### 提取阈值

- 同一交互模式重复 3 次以上，再抽通用组件
- 仅服务单一业务语义的组件，保留在对应 `features/`
- 只有在多个功能都需要时，才进入 `shared/ui`

### 共享代码规则

- 工具函数按"纯函数优先"放入 `shared/lib`
- 类型定义优先跟随业务模块，只有跨模块复用时才上提
- 常量和枚举按功能归属管理，不建无语义的全局常量池

## 7. 样式系统

### 已确认方向

采用 `Tailwind + 语义化 Token` 的方式，兼顾开发速度和后续主题扩展。

### Token 与主题规则

- 禁止在业务组件里直接散落魔法色值
- 所有主色、边框色、背景色、危险态、成功态统一映射为语义 Token
- 暗色模式通过根节点主题切换，不在组件里写分裂逻辑

### 响应式与动效规则

- 响应式以桌面优先，覆盖常见 1440、1280、768 三档
- 动效仅用于层级切换、面板展开、悬停反馈
- 避免大面积复杂动画，优先保证编辑体验稳定

## 8. 实施计划

### 阶段 1

- [ ] 完成信息架构和页面骨架
- [ ] 建立主题 Token 和基础组件
- [ ] 接入笔记列表、笔记详情、标签筛选的核心流程

### 阶段 2

- [ ] 接入编辑器能力
- [ ] 实现全局搜索与筛选联动
- [ ] 完成暗色模式和响应式适配

### 阶段 3

- [ ] 整理共享组件边界
- [ ] 优化列表性能和编辑体验
- [ ] 评估桌面容器或移动端扩展方案

### 依赖关系

编辑器接入依赖基础主题和布局骨架先稳定。搜索体验优化依赖笔记数据结构先定型。

### 优先级说明

第一优先级是"记录、浏览、搜索"闭环，协作、离线、复杂同步都放到后续阶段。
